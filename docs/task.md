# Постановка прикладной задачи

## 1. Назначение программы

Разработать программную систему проверки научных публикаций. Система получает
записи из JSON-выгрузки Crossref, проверяет библиографические данные,
нормализует DOI и ISSN, сопоставляет сведения с критериями проверки и
формирует результаты. Для отклонённых записей сохраняется причина.

## 2. Входные данные

1. JSON-файл ответа Crossref. Записи находятся в `message.items`.
2. Файл `config/criteria.yaml` с версией реестра, максимальным уровнем издания,
   отчётным периодом и требованием к аффилиации.
3. Справочные сведения об изданиях и аффилиации, если они предоставлены.

## 3. Выходные данные

1. Количество обработанных, принятых и отклонённых записей.
2. Результаты проверки каждой публикации.
3. Журнал отклонённых записей с DOI и причиной.
4. Сообщение об ошибке, если входной файл невозможно прочитать или разобрать.

## 4. Правила обработки

1. Прочитать JSON и извлечь список `message.items`.
2. Проверить наличие и типы необходимых полей.
3. Нормализовать DOI: удалить допустимый URL-префикс, пробелы по краям
   и привести идентификатор к нижнему регистру.
4. Нормализовать ISSN: удалить дефисы и пробелы, привести буквы к верхнему
   регистру и проверить формат.
5. Применить критерии из `config/criteria.yaml` к году, уровню издания
   и аффилиации.
6. Зафиксировать результат проверки каждой записи и причину отклонения.
7. Сформировать итоговую сводку и выходные файлы.

## 5. Исключительные случаи

| Исключительный случай | Как обрабатывается |
|---|---|
| Входной файл отсутствует | Вывести сообщение об ошибке; обработку не начинать. |
| JSON имеет некорректный синтаксис | Вывести сообщение об ошибке формата. |
| В ответе нет `message.items` | Сообщить об отсутствии списка записей. |
| DOI отсутствует или имеет неверный формат | Зафиксировать причину отклонения записи. |
| Название публикации пустое | Отклонить запись при проверке модели данных. |
| ISSN имеет неверный формат | Не использовать значение как корректный ISSN. |
| Год публикации отсутствует | Не считать соответствие периоду подтверждённым. |
| DOI повторяется после нормализации | Выявить повтор и отметить записи для проверки. |
| Год не входит в отчётный период | Не засчитывать публикацию по критерию периода. |
| Конфигурация отсутствует или некорректна | Вывести ошибку и не применять неподтверждённые критерии. |

## 6. Проверяемые требования

| № | Требование | Способ проверки |
|---:|---|---|
| 1 | Программа извлекает записи из `message.items`. | Запуск на тестовом JSON. |
| 2 | ISSN `0040-6090` нормализуется в `00406090`. | Автоматическая проверка функции. |
| 3 | Для `None` и числа `40` функция ISSN возвращает `None`. | Проверка граничных значений. |
| 4 | Отсутствующий входной файл приводит к сообщению об ошибке. | Запуск с несуществующим путём. |
| 5 | Каждая отклонённая запись имеет причину. | Проверка журнала отклонений. |
| 6 | Итог содержит число принятых и отклонённых записей. | Проверка вывода программы. |
| 7 | Отчётный период читается из YAML-конфигурации. | Изменение периода и проверка обработки. |
| 8 | При обязательной аффилиации запись без неё не проходит критерий. | Проверка двух разных записей. |

## 7. Границы практической работы

В ПР № 1 создаются проект, конфигурация и постановка задачи, а также
исправляется учебная функция нормализации ISSN. Загрузка Crossref, полная
проверка публикаций и журнал отклонений реализуются в последующих работах.
